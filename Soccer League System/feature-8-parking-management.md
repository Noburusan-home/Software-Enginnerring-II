# Feature: Parking Management

**Feature ID:** 8
**Branch pattern:** `feature/8-parking-management`
**Status:** Draft
**Created:** 2026-10-29
**Input:** Let administrators manage the park's parking lots, daily lot status, and reserved parking passes so game-day traffic is organized and visitors know where to park.
**Depends on:** [Feature 1 — User Authentication & Roles](feature-1-user-authentication-roles.md), [Feature 3 — Park Field Map](feature-3-park-field-map.md)

---

## User Stories

### US-8.1: Define parking lots
**As a** league administrator
**I want to** add parking lots with capacity and map location
**So that** the league has a complete record of available parking

**Priority:** P1
**Independent test:** Create a lot and see it in the lot list and on the map.
**Acceptance scenarios:** see ### US-8.1 under Acceptance Criteria

### US-8.2: Set lot status for a game day
**As a** league administrator
**I want to** mark each lot `open`, `full`, or `closed` for a date
**So that** visitors are directed to lots that have space

**Priority:** P1
**Independent test:** Mark a lot `full` for today and see it flagged on the public page.
**Acceptance scenarios:** see ### US-8.2 under Acceptance Criteria

### US-8.3: View parking information
**As a** visitor
**I want to** see lots, their status today, and where they are on the map
**So that** I can park quickly and get to my field

**Priority:** P1
**Independent test:** Open the parking page without signing in and see each lot with today's status.
**Acceptance scenarios:** see ### US-8.3 under Acceptance Criteria

### US-8.4: Issue reserved parking passes
**As a** league administrator
**I want to** issue a reserved parking pass to a manager, volunteer, or sponsor for a date
**So that** key people have a guaranteed place to park

**Priority:** P2
**Independent test:** Issue a pass for a date and see it listed with a pass code.
**Acceptance scenarios:** see ### US-8.4 under Acceptance Criteria

### US-8.5: View my parking passes
**As a** signed-in user
**I want to** see the parking passes issued to me
**So that** I know where and when I can park

**Priority:** P2
**Independent test:** Sign in as a pass holder and see only my passes.
**Acceptance scenarios:** see ### US-8.5 under Acceptance Criteria

## Functional Requirements

- **FR-001**: Only an `admin` MUST be able to create, edit, or deactivate lots, set daily status, or issue passes.
- **FR-002**: A parking lot MUST have a name, total spaces, and a map location.
- **FR-003**: A lot name MUST be unique.
- **FR-004**: A lot's map location MUST reference a map point of type `PARKING_LOT` and MUST NOT be shared with another lot.
- **FR-005**: Total spaces MUST be a positive integer; reserved spaces MUST be 0 or more and MUST NOT exceed total spaces.
- **FR-006**: Daily lot status MUST be one of `open`, `full`, `closed`.
- **FR-007**: A lot with no status for a date MUST be shown as `open`.
- **FR-008**: A lot MUST NOT have more than one status entry per date.
- **FR-009**: The parking page MUST be viewable without signing in.
- **FR-010**: A pass MUST belong to exactly one holder, either a user or a sponsor.
- **FR-011**: A pass MUST have a lot, a valid date, and a unique pass code generated by the system.
- **FR-012**: The number of active passes for a lot on a date MUST NOT exceed that lot's reserved spaces.
- **FR-013**: Passes MUST be revocable; a revoked pass MUST keep its history and no longer count toward reserved spaces.
- **FR-014**: A user MUST only see their own passes; an `admin` MUST see all passes.

---

## Key Entities

- **Parking Lot**: a parking area with capacity, reserved spaces, accessibility flag, and map location.
- **Lot Day Status**: the open/full/closed state of a lot on one date.
- **Parking Pass**: a reserved parking permit for a user or sponsor on one date at one lot.
- **Map Point**: the lot's location marker (Feature 3).

## Initial Data Model

### `parking_lots` table
| Field | Type | Rules |
|-------|------|-------|
| `id` | INTEGER PK | Auto-increment |
| `name` | STRING(100) | Required, unique |
| `mapPointId` | INTEGER FK | Required, unique, references `map_points.id` (type `PARKING_LOT`) |
| `totalSpaces` | INTEGER | Required, > 0 |
| `reservedSpaces` | INTEGER | Required, default 0, <= `totalSpaces` |
| `hasAccessibleSpaces` | BOOLEAN | Required, default `false` |
| `status` | ENUM(`active`,`inactive`) | Required, default `active` |

### `parking_lot_day_status` table
| Field | Type | Rules |
|-------|------|-------|
| `id` | INTEGER PK | Auto-increment |
| `parkingLotId` | INTEGER FK | Required, references `parking_lots.id` |
| `statusDate` | DATE | Required; unique with `parkingLotId` |
| `lotStatus` | ENUM(`open`,`full`,`closed`) | Required |
| `note` | STRING(255) | Optional |

### `parking_passes` table
| Field | Type | Rules |
|-------|------|-------|
| `id` | INTEGER PK | Auto-increment |
| `parkingLotId` | INTEGER FK | Required, references `parking_lots.id` |
| `holderUserId` | INTEGER FK | Optional, references `users.id` |
| `holderSponsorId` | INTEGER FK | Optional, references `sponsors.id` |
| | | Exactly one of `holderUserId` / `holderSponsorId` required |
| `passDate` | DATE | Required |
| `passCode` | STRING(20) | Required, unique, system-generated |
| `status` | ENUM(`active`,`revoked`) | Required, default `active` |

## Acceptance Criteria

### US-8.1 — Define parking lots

#### Scenario: Admin creates a parking lot
*   **Given** I am signed in as an `admin`
*   **And** an unused `PARKING_LOT` map point `East Lot Spot` exists
*   **When** I enter name `East Lot`, total spaces `120`, reserved spaces `10`, and select that map point
*   **Then** the API returns `201` with `status` equal to `active`

#### Scenario: Reserved spaces greater than total is rejected
*   **Given** I am signed in as an `admin`
*   **When** I enter total spaces `50` and reserved spaces `60`
*   **Then** the API returns `400` with `{ "message": "Reserved spaces cannot exceed total spaces." }`

#### Scenario: Duplicate lot name is rejected
*   **Given** a lot named `East Lot` exists
*   **When** I create another lot named `East Lot`
*   **Then** the API returns `409` with `{ "message": "A parking lot with this name already exists." }`

### US-8.2 — Set lot status for a game day

#### Scenario: Admin marks a lot full for a date
*   **Given** I am signed in as an `admin` and `East Lot` exists
*   **When** I set status `full` for `2026-11-14` with note `Overflow to South Lot`
*   **Then** the API returns `200` with `lotStatus` equal to `full`

#### Scenario: Updating an existing day replaces the status
*   **Given** `East Lot` is `full` on `2026-11-14`
*   **When** I set status `open` for `2026-11-14`
*   **Then** only one status entry exists for that date
*   **And** its `lotStatus` is `open`

#### Scenario: Invalid status is rejected
*   **Given** I am signed in as an `admin`
*   **When** I submit status `crowded`
*   **Then** the API returns `400` with `{ "message": "Status must be open, full, or closed." }`

### US-8.3 — View parking information

#### Scenario: Visitor sees today's status for each lot
*   **Given** `East Lot` is `full` today and `South Lot` has no status entry
*   **When** I open the parking page without signing in
*   **Then** `East Lot` shows `Full`
*   **And** `South Lot` shows `Open`

#### Scenario: Visitor opens a lot on the map
*   **Given** `East Lot` has a map location
*   **When** I click **Show on map** for `East Lot`
*   **Then** the park map opens with the `East Lot` marker highlighted

### US-8.4 — Issue reserved parking passes

#### Scenario: Admin issues a pass to a user
*   **Given** I am signed in as an `admin`
*   **And** `East Lot` has `10` reserved spaces and no passes for `2026-11-14`
*   **When** I issue a pass to `maria@example.com` for `2026-11-14`
*   **Then** the API returns `201` with a unique `passCode`

#### Scenario: Pass exceeding reserved spaces is rejected
*   **Given** `East Lot` has `1` reserved space and one active pass for `2026-11-14`
*   **When** I issue another pass for `2026-11-14`
*   **Then** the API returns `409` with `{ "message": "No reserved spaces left for that date." }`

#### Scenario: Pass with two holders is rejected
*   **Given** I am signed in as an `admin`
*   **When** I submit a pass with both a user and a sponsor as holder
*   **Then** the API returns `400` with `{ "message": "Choose either a user or a sponsor." }`

#### Scenario: Admin revokes a pass
*   **Given** an active pass exists
*   **When** I click **Revoke** and confirm
*   **Then** the pass `status` is `revoked`
*   **And** the reserved space is available again for that date

### US-8.5 — View my parking passes

#### Scenario: User sees only their own passes
*   **Given** I am signed in as `maria@example.com` with one active pass
*   **And** another user also has a pass
*   **When** I open **My parking passes**
*   **Then** I see exactly one pass with its lot, date, and pass code

#### Scenario: User with no passes
*   **Given** I am signed in and have no passes
*   **When** I open **My parking passes**
*   **Then** I see `You have no parking passes.`

## Screen Requirements

### Screen: Parking Information (Public)
**Route:** `/parking` | **Access:** Public

| Element | Details |
|---------|---------|
| Date picker | Defaults to today |
| Lot cards | Name, spaces, accessible-parking icon, status badge (`Open` green, `Full` red, `Closed` grey) |
| Note | Shows the lot's note for the date if present |
| **Show on map** | Link to `/map` with the lot highlighted |

### Screen: Parking Lot Management
**Route:** `/admin/parking` | **Access:** `admin`

| Element | Details |
|---------|---------|
| Lots table | Columns: Name, Total, Reserved, Accessible, Status |
| **Add lot** | Form: name, map point dropdown, total, reserved, accessible toggle |
| Day status panel | Pick lot and date, choose status, optional note, **Save** |

### Screen: Parking Passes (Admin)
**Route:** `/admin/parking/passes` | **Access:** `admin`

| Element | Details |
|---------|---------|
| Passes table | Columns: Holder, Lot, Date, Pass code, Status |
| **Issue pass** | Form: lot, date, holder type (User/Sponsor), holder dropdown |
| **Revoke** | Row action with confirmation dialog |

### Screen: My Parking Passes
**Route:** `/my/parking` | **Access:** Signed-in users

| Element | Details |
|---------|---------|
| Pass cards | Lot name, date, pass code, **Show on map** |
| Empty state | "You have no parking passes." |
